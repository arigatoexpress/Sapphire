# TradingView Webhook Setup

Quick reference for wiring TradingView alerts into the Sapphire signal pipeline.

## Current endpoint

| Environment | URL |
|-------------|-----|
| Production (persistent) | `https://webhook.sapphirealpha.xyz/webhook/tradingview` |
| Quick tunnel (temporary) | Run `cloudflared tunnel --url http://localhost:9090` on the Windows PC and use the printed `*.trycloudflare.com` URL |

For a persistent URL, set up the named Cloudflare Tunnel:
`infra/cloudflare/setup-windows-tunnel.ps1` (requires browser auth).

## Webhook secret

Set `WEBHOOK_SECRET` in the environment of `services/webhook/src/receiver.py`.
The receiver accepts the secret via:

- Header: `X-Sapphire-Webhook-Secret`, `X-TradingView-Secret`, or `X-Webhook-Secret`
- Body field: `secret`, `webhook_secret`, or `passphrase`

If `WEBHOOK_SECRET` is unset, all webhooks are accepted (not recommended for production).

## Pine Script alert template

Paste the generated indicator into TradingView Pine Editor, add it to the chart,
and create an alert with the message template shown below.

### Generated file

- Source: `pine/generated/sapphire_watch_BTCUSDT.pine`
- Metadata: `pine/generated/sapphire_watch_BTCUSDT.json`

### Alert message (auto-generated by the script)

The Pine script emits JSON automatically:

```json
{"symbol": "BTCUSDT", "action": "long", "price": <close>, "strategy": "sapphire_watch_indicator", "source": "tradingview_pine", "interval": "<timeframe>", "exchange": "BINANCE", "time": <time>}
```

Supported actions: `long`, `short`, `exit_long`, `exit_short`.

### Recommended TradingView alert settings

- Frequency: **Once Per Bar Close** (`alert.freq_once_per_bar_close`)
- Webhook URL: `https://webhook.sapphirealpha.xyz/webhook/tradingview`
- Optional: include `secret` field in the alert message or use the `X-Webhook-Secret` header.

## Signal routing

The receiver forwards validated alerts to env-driven targets:

- `SIGNAL_TARGETS=mac-logger=http://host:18081,desk=http://host:18082`
- Legacy: `SIGNAL_LOGGER_MAC`, `ALPHA_ENGINE_RARI1`, `ALPHA_ENGINE_RARI2`

If no targets are configured, the webhook is accepted and logged but not forwarded.

## Idempotency

Duplicate alerts with the same `(symbol, action, time, exchange, interval, strategy)`
fingerprint within `IDEMPOTENCY_WINDOW_SECONDS` (default 300s) are returned as
`{"status": "duplicate"}` with HTTP 200. This prevents double-fills when TradingView
retries on timeout.

## Verification

```bash
# Health check
curl https://webhook.sapphirealpha.xyz/health

# Test signal (omit secret if unconfigured)
curl -X POST https://webhook.sapphirealpha.xyz/webhook/tradingview \
  -H 'Content-Type: application/json' \
  -H 'X-Sapphire-Webhook-Secret: <WEBHOOK_SECRET>' \
  -d '{"symbol":"BTCUSDT","action":"buy","price":100000,"time":1234567890}'
```

## Windows host

The receiver runs on the Windows PC at `0.0.0.0:9090`. It is brought up by the
existing TradingView webhook service/scheduled task. The Cloudflare Tunnel forwards
public HTTPS traffic to `http://localhost:9090` on that host.
