How is Sapphire feeling right now?

One-glance status of the whole system. Green means everything is nominal; amber means at least one service is degraded; red means a critical service is down or the killswitch tripped.

How does this work?

The hero polls /api/system every 60 seconds. It counts how many of the registered services (control-plane, dashboard, signal-logger, inference-proxy, hermes, etc.) report healthy, plus how many of the four inference tiers (Windows GPU, Pi rari1/rari2, Mac local, Kimi cloud) are currently online.

Thresholds: ≥80% healthy = Nominal, 50–79% = Degraded, <50% = Critical.

The four numbers that matter most today

Service health, inference redundancy, today's signal count, and Pi cluster availability — refreshed every minute. Use these to decide whether the platform is safe to lean on.

How does this work?

Each KPI tile is a thin formatter over a JSON endpoint:

  • Services healthy — count of services in /api/system with healthy: true.
  • Inference tiers — count of tiers in /api/system.inference.endpoints reporting healthy.
  • Signals today — total + win-rate from /api/signals.stats (data/signals/*.jsonl, deduplicated).
  • Pi cluster — boolean health of pi-rari1 + pi-rari2.

Sparklines come from /api/metrics/history.

Which services and AI brains are online?

Left: every long-running Sapphire service and its port. Right: the four-tier AI inference fallback chain — your Telegram bot will keep answering even if the GPU server goes offline.

How does this work?

Each service entry probes its own /health endpoint via the proxy and reports healthy / unhealthy / unknown. Inference tiers cascade in this order:

  • T1 — Windows GPU (RTX 5070 Ti, 27 models). Fastest path, ~0.4s.
  • T2 — Raspberry Pi rari1 / rari2 (small models, ARM).
  • T3 — Mac local (Ollama on this machine, CPU fallback ~90s).
  • T4 — Kimi cloud (non-sensitive prompts only — regex blocks API keys, passwords, JWTs).

The proxy auto-fails-over: if T1 returns 503, the request retries against T2, then T3, then T4. Tier latencies come from /metrics on the inference proxy.
