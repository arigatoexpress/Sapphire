The Sapphire Book
Operational Manual & System Documentation
Version 2.0 | Classification: OPERATOR
01 System Overview [+]

Sapphire is an autonomous trading and operations platform designed for 24/7 market participation with minimal human intervention. The system consists of:

  • Alpha Engine: Core signal generation and execution logic
  • Gateway: API routing and webhook ingress
  • PM Hub: Project management and operational governance
  • Edge Infrastructure: Raspberry Pi nodes for trade execution

All components communicate via encrypted channels with health monitoring and automatic failover.

02 Architecture [+]

Sapphire uses a hub-and-spoke architecture with the Unified Frontend as the central coordination point:

Cloud Layer

  • Google Cloud Run for stateless services
  • Cloud Firestore for persistent data
  • Cloud Scheduler for automated jobs

Edge Layer

  • RARI-1 & RARI-2: Trading execution nodes
  • Windows Lab: TradingView integration
  • Tailscale mesh for secure connectivity
03 Security Protocols [+]

Sapphire implements defense-in-depth with multiple security layers:

Access Control

  • Basic Auth for API endpoints
  • X-Sapphire-Token for internal jobs
  • Read-only web interface - no mutations

Operational Safety

  • Kill switch for emergency halt
  • Owner approval gate for autonomy
  • Failure pressure monitoring
  • Automatic paper-trade fallback
04 Trading Operations [+]

Trading follows a multi-stage pipeline from signal to execution:

  1. Signal Generation: Alpha Engine produces trading signals
  2. Validation: Risk checks and sanity filters applied
  3. Routing: Signal routed to appropriate execution venue
  4. Execution: Edge node executes via exchange API
  5. Confirmation: Trade logged and PnL tracked

All stages are monitored with telemetry sent to Firestore for analysis.

05 API Reference [+]

Key API endpoints for operators:

Status Endpoints

  • /api/platform/status - Full system status
  • /api/platform/home-snapshot - Aggregated status/metrics/logs snapshot
  • /api/platform/readiness - Readiness gates

Data Endpoints

  • /api/platform/metrics - Trading metrics
  • /api/platform/logs - Activity logs
  • /api/platform/trades - Trade history

Management Endpoints

  • /api/platform/projects - Program portfolio
  • /api/platform/organization - Org structure
  • /api/platform/contracts - API manifest
06 Troubleshooting [+]

Common Issues

Service Degraded: Check /api/platform/status for unhealthy services. Restart via Cloud Console if needed.

Edge Node Offline: Verify Tailscale connection on the node. Check power and network.

Signal Not Executing: Verify dex_execution_stage is not 'paper' and kill_switch is not active.

Emergency Procedures

  • Activate kill switch via macOS Commander app
  • Contact operator via Telegram bot
  • Check Cloud Run logs in GCP Console
